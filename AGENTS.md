# Инструкция для людей и coding-агентов

Это репозиторий движка, а не готовая игра. Перед работой прочитай только:

1. `README.md` — назначение и команды;
2. `docs/STATUS.md` — единственный краткий реестр состояния;
3. `docs/HANDOFF.md` — текущая незакрытая задача;
4. карточку задачи из `docs/tasks/`;
5. нужные разделы `docs/SPECIFICATION.md`.

Не пытайся реализовать весь документ одним запросом. Единица работы — одна bounded-карточка с проверяемым результатом. Если требования противоречат коду, зафиксируй решение в `docs/decisions/` и обнови статус; не прячь расхождение в комментарии.

Правила ядра:

- `packages/contracts` — источник публичных типов первого слоя;
- `packages/core` — чистые вычисления; без HTTP, React, SQLite, Cloudflare, секретов и сетевых вызовов;
- модель не изменяет игровой state напрямую; сначала формируется проверяемый результат, затем будущий runtime применит его атомарно;
- `needs_clarification`, `unsupported`, `failed` не являются игровыми исходами;
- незавершённое не помечается готовым.

После изменения запускай относящиеся проверки и записывай фактический результат в handoff/worklog. Не добавляй новый общий prompt или Skill, если короткая ссылка на схему и рецепт решает задачу. Секреты и ключи в git не попадают.
