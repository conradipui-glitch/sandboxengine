# Приоритет MVP до 14 октября

Дата — рабочая цель хакатона, переданная командой; этот файл не подтверждает внешние правила отбора. Для демонстрации нужен один законченный playable vertical slice, а не вся платформа.

## В MVP обязательно

1. одна кампания с понятным началом, несколькими решениями и финалом;
2. свободная формулировка хода в пределах объявленных механик;
3. причинный state на серверной стороне или в авторитетном Engine;
4. честные исходы `executed`, `partial`, `conditional`, `blocked` и отсутствие скрытого изменения мира рассказчиком;
5. минимум одна визуальная сцена/переход, связанная с результатом через `SceneFrame`/`PresentationPlan`;
6. короткий авторский путь: создать или изменить данные кампании, проверить предпросмотр, воспроизвести сценарий;
7. ручной плейтест и запись известных ограничений.

## В MVP не входит

Полный каталог провайдеров, универсальный Builder, все плагины, несколько облаков, бесконечная кампания и идеальная Studio. Их границы должны оставаться расширяемыми, но они не должны задерживать первый доказанный маршрут.

## Рабочий порядок

Для hackathon-среза допустимо перенести минимальную часть существующей Florence раньше полного авторского помощника: `baseline → contracts/core → runtime slice → один клиентский путь → миграционный adapter → плейтест`. Это изменение порядка поставки, оформленное в [ADR-0002](decisions/0002-mvp-delivery-order.md); оно не отменяет контрактные инварианты и не объявляет B11 или B12 выполненными.
