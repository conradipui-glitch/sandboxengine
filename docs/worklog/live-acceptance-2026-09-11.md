### Известные расхождения (из чтения кода; живым прогоном не подтверждались)

- **Доска и доска сюжета не имеют data-action на узлах и рёбрах** — Карточки и связи ищутся по классу и атрибуту ('.board-node[data-node-id]', '.board-edge[data-edge-id]', '.story-node[data-node-id]', '.story-edge[data-edge-id]'); кнопки «Связать» и «Вписать всё» — вообще только по тексту (story-dom.ts создаёт их без data-action). Сценарий вынужден искать кнопки по textContent, а не по стабильному контракту. _(код: apps/studio/src/board-dom.ts, apps/studio/src/story-dom.ts)_
- **Связь на доске не создаётся кликом: нужен синтез PointerEvent** — board-dom.ts слушает 'pointerdown' на вьюпорте, а 'pointermove'/'pointerup' — на карточке-источнике; цель определяется через document.elementFromPoint(clientX, clientY). Инструмент click из scripts/l07-cdp.mjs (element.click()) здесь неприменим: дисплей-клик не порождает pointerdown, пришлось синтезировать PointerEvent и отправлять pointerup на источник. _(код: apps/studio/src/board-dom.ts (onPointerDown/startConnectDrag/capturePointer))_
- **Связь на доске сюжета — трёхшаговый режим** — Сначала включается режим «Связать», затем клик по сцене-источнику, затем по цели, и только потом Studio открывает диалог с подписью выбора. Один «шаг связи» в UI — это три действия плюс модальная форма; в сценарии разложено на подшаги. _(код: apps/studio/src/app.ts (hint «Связать»), story-dom.ts (connectMode))_
- **Форма запуска выпуска появляется только после valid-проверки** — renderReleaseBuildForm возвращает подсказку вместо формы, пока нет valid validation точно текущей revision и content hash. Шаг публикации обязан сначала дождаться проверки; «просто нажать Опубликовать» после правок нельзя. _(код: apps/studio/src/versions.ts (renderReleaseBuildForm), apps/studio/src/app.ts (prepareReleaseBuild))_
- **Форма добавления слоя спрятана в закрытом <details>** — Композиция слоя ('data-form="screen-layer-add"') лежит внутри <details class="screen-layer-add">; в закрытом details элементы не отрисовываются, поэтому перед заполнением сценарий обязан раскрыть details — иначе клик/ввод промахивается. _(код: apps/studio/src/app.ts (renderScreenEditor))_
- **Настоящий asset для фона требует assetId И sha256 из 64 hex** — Фон/музыка/слой принимаются только парой (assetId, hash), а слой без asset допустим. Живой фон требует реальной библиотеки материалов, которой в срезе FIN-05 нет, поэтому шаг «экраны» правит документированный inheritBackground, а «материалы» добавляют текстовый слой без asset — без подделки хешей. _(код: apps/studio/src/app.ts (renderScreenEditor), apps/studio/src/screen-model.ts)_
- **Публичный каталог недоступен через origin Studio** — Studio-прокси обслуживает только '/control/*'; '/public/v1/missions' через него отдаёт 404 (serveStatic). Проверка каталога сайта поэтому идёт вторым, отдельным CLI-адресом Control — иначе шаг «каталог» недостижим из браузерной сессии Studio. _(код: apps/studio/src/dev-server.ts (serveStatic/proxyControl))_
- **Сид миссии уже содержит выбор и финал** — createMission создаёт вход → выбор «Завершить» → финал. Буквальные «два выбора и два финала» недостижимы без удаления сид-выбора, поэтому после двух добавленных связей в сюжете фактически три выбора и два финала; расхождение фиксируется, а не подгоняется. _(код: apps/studio/src/app.ts (createMission))_
