# Сводный аудит Living History — 2026-09-12 (по скиллам game-design / office-web-ui-system / headless-game-balance / game-architect / design-coherence-engine)

Источники: 5 параллельных read-only аудитов (deleg_4a1bfe90), проверялись SHA `feat/b13-acceptance-closure`.

## Топ-проблемы (кросс-аудит)

### A. Ядро игры (дизайн-аудит)
1. **P0·баг:** канонический маршрут Florence падает: `public` case-2 добавляет +1 к `contract-rights`, когда он уже max=1 → `resource_out_of_bounds` → весь ход отбрасывается. Флагманский путь не проходим.
2. **P0:** дилемма живёт вне движка: `sidecarBeatsToMissionStory` схлопывает 3 опции бита в 1 кнопку и 3 финала в один `legacy-end`; `clockAdvanceSeconds` и case-условия не входят в `MissionChoice`. Ядро не исполняет Florence честно.
3. **P0:** мёртвые ресурсы: `clock` не потребляет ничто (время бесплатно), `fresco-progress` не читает ни один финал/кейс, кэш почти не тратится. «Мастерская под давлением» без давления.
4. **P1:** доминирующая линия `draft→ledger→counter→pigment→public→sign` — единственный путь к лучшему финалу; остальные опции наказаны. Чинить порогами-ИЛИ, не нерфом.
5. **P1:** `blocked`-выборы без причины — игрок перебирает вслепую. Нужен reason («нужно доверие гильдии 3»).

### B. UX/обучение (UX-аудит)
1. **P0:** модали без Escape и клика-по-подложке (проект/карточка/story-dialog) — пользователь заперт в окне. Единый модальный менеджер.
2. **P0:** «Создать квест/С ИИ» на карточке ничего не создаёт (только открывает редактор) — нечестный сигнифер. Плюс двойная форма названия (story-mission-create не пишет в quest.title).
3. **P1:** два разных документа за тремя видами (Доска/Список = draft-блоки, Сюжет = mission story) без подписи-ориентира — корень «куча блоков, непонятно как связаны».
4. **P1:** один канал обратной связи на всё (topbar-status); ошибки рядом с действием отсутствуют.
5. **P1:** два дублирующих текстовых тура; первый запуск должен быть интерактивным (действие, не чтение). После «Создать с ИИ» автор попадает на Доску вместо вида «Сюжет».

### C. Баланс/симуляция (баланс-аудит)
- Ядро готово к headless-симуляции (чистые функции, seeded RNG, конфиг-JSON) — все пункты чек-листа PASS.
- Florence = всего 729 маршрутов (6 битов × 3 опции, RNG не участвует) — **исчерпывающий перебор возможен уже сейчас**.
- Инварианты записаны: INV-1 idle не выигрывает; INV-2 аванс ≠ право; INV-3 условные опции честны; INV-4 порядок значим.
- Первый симулятор: политика random-legal-v1, сиды sim-smoke-1..5, метрики (terminal.reason, финальные ресурсы, elapsedSeconds); второй шаг — exhaustive-режим как эталон.

### D. Архитектура (арх-аудит)
- Факт: data-driven — ведущая парадигма; «DDD-ядро» = чистое доменное ядро поверх data (агрегаты-объекты не нужны, это осознанно).
- **Расхождение с ADR-0014:** ход сюжетной миссии исполняется в `control` (`MissionSessionStore.applyMissionTurn`), а не в runtime — нужен ADR (принять как есть или вынести; таблицы `control_*` труднообратимы).
- Кандидаты ADR: (1) где исполняется ход; (2) судьба двух моделей контента (блочный граф vs story-документ); (3) Application Layer фактически в apps/server, а не в runtime (SPEC §4.1 врёт).
- Мелочь: мусорные `*.sqlite-wal`/`.tmp-*.sqlite` в корне репо.

### E. Контуры продукта (контур-аудит)
1. **P0:** `meta[name="lh-site-base"]` не инжектится нигде → кнопка публикации всегда «адрес сайта не настроен»; маршрут `/p/<id>/` живёт только в ветке `9cb94d3`, в доставляемую `wave2 d5022c8` не влит.
2. **P1:** published-ходы не пишут аналитику (ProductAnalytics только legacy; engine-метрики 501) — петля «игрок → данные → автор» не существует.
3. **P1:** финал не ведёт к следующей миссии (только «Начать заново»/«К сценариям»); каталог не знает пройденного.
4. **P2:** сайт жёстко ставит всем карточкам `difficulty: "Доступно"`, выбрасывает `supportedModes`/`estimatedMinutes` из каталога — висячая механика режимов.
5. **P2:** темы разъехались: Studio — изумрудный акцент, сайт — кирпично-красный пергамент; ADR 2026-09-10 объявил сайт источником токенов.

## План (сверка с идущими зонами)

**W1 — уже в работе (фан-аут реализации, ветки от b96738f):**
AI-CHAIN (чат-агент создания миссий), OFFICE-UI (архетипы+локаторы+вкладка-во-вкладке), GLITCH-SWEEP (глюки окон/тем), E2E-LOOP (сквозной цикл со скриншотами), GUIDE (5 шагов первой миссии). UX-аудит §B.1–B.2 закрывается зонами OFFICE-UI/GLITCH-SWEEP/GUIDE.

**W2 — сразу после W1 (P0-движок, новая волна):**
1. Починить `resource_out_of_bounds` на каноническом маршруте (clamp/exclusive-семантика флагов).
2. Дотащить дилемму в контракт: `clockAdvanceSeconds`+case-семантика в `MissionChoice`, sidecar 3 опции = 3 choice, 3 финала = 3 endings.
3. Потребители стоимости: дедлайн по `elapsedSeconds` в условиях финала, приёмка `deliver` по `fresco-progress`.
4. `reason` для blocked-выборов + рендер порогов в PlayerView.
5. Инжект `lh-site-base` в Studio + влить `/p/<identifier>/` в доставляемую ветку сайта.
6. ADR по трём кандидатам арх-аудита (решение владельца для №1 — исполнение хода).

**W3 — P1:**
- Симулятор баланса (exhaustive 729 → 4 инварианта как автотесты).
- Слом доминантной линии порогами-ИЛИ (counter: записи ИЛИ объём; кэш открывает опции).
- Аналитика published-ходов; CTA «Другая миссия» + «пройдено» в каталоге.
- Слияние двух туров в один интерактивный; переключение в «Сюжет» после ai-draft.
- Синхронизация темы Studio с токенами сайта.

**W4 — P2:** честные `difficulty/supportedModes` в каталоге сайта; lineage копий миссий; архив релизов при удалении.

## Верификация приёмки (стандарт владельца)
Каждый пункт W2–W3 закрывается: тест + скриншот на живом стенде + запись в E2E-LOOP отчёт. Итоговая приёмка — полный прогон ui-visual-acceptance (16 экранов) на доставленном стенде.
