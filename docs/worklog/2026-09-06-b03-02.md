# Worklog — 2026-09-06 — B03-02

## Цель

Добавить поверх B03-01 первый чистый scheduler state-transition: due events применяются по игровому времени, а успешный интервал коммитит clock/revision один раз.

## Реализовано

- отдельный strict `ScheduledEffectEvent:1.0` вместо silent widening `ScheduledEvent:1.0`;
- kind `core.effects` с bounded `GameplayEffect[]`;
- Core `SchedulerEvent = marker | effect-event`;
- B03-01 planner поддерживает оба event contract без изменения boundary/order semantics;
- `applyTimeAdvancePlan`;
- plan/state clock matching;
- sequential due-event application через B02 `tryApplyEffectBatch`;
- marker events как trace/no-op;
- whole-transition failure без partial state;
- successful clock=end и revision+1 ровно один раз;
- zero-duration commit policy зафиксирована;
- pending events не применяются и возвращаются отдельно;
- malformed/unsorted plan, revision overflow и event effect failure — explicit failures;
- generated agent capabilities содержат `core.effects` и `core.marker`.

## Опорные регрессии

### Chronology

Начальное `blue_paint=2`. Input-массив специально передан в обратном причинном порядке:

1. spend at 400 sec: `-4`;
2. delivery at 300 sec: `+2`.

Planner сортирует по игровому времени: delivery → spend. Scheduler применяет +2, затем -4 и получает final resource=0, clock=600, revision 7→8. Порядок массива не является источником причинности.

### Whole-transition atomicity

- event A at 300 успешно даёт `blue_paint +2`;
- event B at 400 пытается передать item несуществующему holder;
- transition возвращает `event_effect_failed / holder_not_found` без `state`;
- authoritative input остаётся paint=2, item остаётся в исходной location.
