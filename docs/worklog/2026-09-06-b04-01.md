# 2026-09-06 — B04-01 operation/storage Memory semantics

## Цель

Создать первый реальный runtime/storage слой поверх принятого B03: idempotency, single active owner, service lease, fencing и атомарный semantic commit — пока только в Memory, без SQLite/HTTP.

## Реализовано

- Создан workspace `@living-history/runtime`.
- Добавлены transport-agnostic storage types/result unions и `RuntimeStorage`.
- Добавлены `ServiceClock` и deterministic `ManualServiceClock`.
- Реализован `MemoryRuntimeStorage` как reference state machine.
- Same completed key/hash возвращает persisted response; replay проверяется раньше текущей revision.
- Request SHA-256 канонизируется в lowercase; uppercase/lowercase hex — одна idempotency identity.
- Same key с другим hash/revision отклоняется.
- Одна active operation на session; concurrent different command отклоняется.
- Expired same request reacquire получает больший fencing token.
- Stale token не может commit после reacquire.
- `commitTurn` проверяет revision/owner/token/lease/candidate/turn/response до публикации и сохраняет state+turn+response+completion вместе.
- `finishWithoutTurn` сохраняет replayable response без изменения game revision.
- Root `test:storage` стал реальным и входит в `verify`.
- `check:boundaries` дополнительно запрещает Core импортировать Runtime.

## Проверки

Final functional gate: CI `34036284044` — success:

Storage regressions:

1. T10 Memory — duplicate commits once, completed response replays, reused key/different hash conflicts; hex casing normalized.
2. T11 Memory — two different commands cannot own one session revision simultaneously.
3. T12 foundation — expired lease reacquire gets higher fencing token; stale worker commit rejected.
4. Invalid candidate commit leaves state/turn/public response untouched.
5. Service lease clock is independent from game clock.
6. `finishWithoutTurn` is replayable and leaves revision unchanged.
7. Lease renewal preserves fencing token and uses injected service time.
