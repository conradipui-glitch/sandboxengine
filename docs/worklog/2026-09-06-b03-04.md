## Почему появился B03-04

B03-03 прошёл свою bounded-приёмку, но повторная сверка с каноническим B03 выявила четыре не закрытых доказательства: exact T05, T06, T08 и same plan+seed replay/hash. Вместо раннего перехода к B04 создан последний bounded B03 slice.

## Реализовано

### Typed entity movement

- `GameplayEffect:1.0` расширен зарегистрированным strict variant `entity.move` в соответствии с ADR 0003.
- Effect содержит только `sourceId`, existing `entityId`, existing `locationId`.
- `tryApplyEffectBatch` переносит entity на trial state и сохраняет atomicity mixed batch.
- missing entity/location → explicit failure без state.
- arbitrary `statePatch` не принимается.

### Dynamic scheduler processing

- Добавлен отдельный `processTimeAdvancePlan`; B03-01 `planTimeAdvance` не изменён по смыслу.
- Initial events получают deterministic sequence после canonical static plan.
- Trusted handler получает frozen state snapshot и может вернуть только strict scheduler events.
- Generated child в прошлое, duplicate/invalid child или handler failure → transition failure без candidate state.
- Same-time child не может перескочить перед parent: effective priority = max(child priority, parent effective priority), затем monotonic sequence.
- Общий `maxSteps/maxEvents` считает initial и generated processing.
- Terminal останавливает processing и оставляет remaining due events unprocessed.

### Fixed first-release priority policy

После первого зелёного B03-04 CI canonical re-audit обнаружил, что §7.4 требует фиксированные приоритеты, а не произвольные author values. Добавлены Core constants:

- `CORE_WORLD_EVENT_PRIORITY = 10`;
- `CORE_TASK_STEP_PRIORITY = 20`;
- `CORE_DEADLINE_PRIORITY = 100`;
- internal synthetic task-start order = `19`.

Task/deadline projection теперь проверяет и использует эту policy; exact T06 переписан на 20-before-100.

### Replay fingerprint

- `buildSchedulerReplayFingerprint` использует существующий `canonicalStringify` + SHA-256.
- Вход: versions, initial state, plan, RNG provenance, processed events, final state.
- Выход: canonical JSON, ordered effects, SHA-256 hash.
- Meaningful change input/provenance/result меняет hash.

## Именованные regressions

- **T05:** NPC starting outside workshop; task completion at 900 делает `entity.move`; event at 1200 видит NPC уже в workshop; long interval заканчивается на 2400.
- **T06:** interval 86_300→86_700; task completion и deadline оба at 86_500; completion priority 20, deadline 100; final clock 86_500; crossing 86_400 происходит только integer arithmetic.
- **T08:** immediate self-generating event chain; `maxSteps=6`; trial effects отбрасываются; authoritative state/clock/revision неизменны.
- **Replay:** same plan+seed/provenance → identical ordered effects/final state/hash; meaningful change → different hash.

## Canonical acceptance

По B03 card из `docs/SPECIFICATION.md` теперь доказаны: integer clock, ordered queue, long action/event chronology, NPC tasks, deadline interruption, generated-event budget, same-time causality, terminal semantics, deterministic RNG/provenance и replay hash. В изменённом Core нет `Math.random`, `Date`, wall-clock timers, HTTP/storage/LLM.

**Решение:** общий B03 принят при условии зелёного final PR gate и последующего merge/push CI. Следующий блок — B04 persistence/runtime/API/idempotency, без изменения принятой Core scheduler semantics.
