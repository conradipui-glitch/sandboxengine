## Goal

Turn an exact successful Control validation into an immutable release, let only the project owner atomically publish/rollback the current release, and make production Runtime start new sessions from that published release while preserving every existing session's exact pinned mechanics.

## Implementation

- Added immutable Memory/SQLite release storage with exact release identity, source validation identity, compiled artifact/hash and B08 sidecars.
- Added release build authority that rechecks draft/validation identity, recomputes canonical artifact SHA-256 and preflights installed plugin compatibility.
- Added explicit empty plugin requirements metadata when no plugin is required.
- Added artifact-bound authored `dice-check` sidecar materialization and tamper checks.
- Added append-only publication history and durable nullable `currentReleaseId`.
- Added idempotent owner-only publish and rollback with expected-current compare-and-set.
- Added rollback eligibility proof: built-but-never-published releases cannot be rollback targets.
- Added Control HTTP release list/build/publish/rollback routes with B09-01 auth, project-role, Origin/CORS and CSRF boundaries.
- Added server-side published release resolver and durable published-session project binding.
- Added Runtime published mode: new sessions resolve current release; existing sessions resolve exact pinned release, not current pointer.
- Added explicit separation between static-template mode and published-release mode; mixed composition fails.
- Replaced standalone production `minimal-paint` fallback with SQLite release store + published binding composition.
- Added SQLite process-like reopen proof for current pointer, existing session binding and continued exact pinned execution.
- Updated endpoint registry and deterministic generated agent/OpenAPI contracts to expose only implemented B09-02 release operations.

## Semantic hardening findings

The post-green audit found and resolved four acceptance-level gaps rather than accepting a merely green partial slice:

1. release storage/authority existed before the Control HTTP authority was actually exposed;
2. a global/static execution context would have allowed old sessions to execute newer published mechanics;
3. standalone production composition still used the static `minimal-paint` template;
4. durable release pointer alone did not prove existing published-session execution after process reopen.

All four were closed with deterministic regressions. Endpoint/generated-doc truth was then synchronized separately.
