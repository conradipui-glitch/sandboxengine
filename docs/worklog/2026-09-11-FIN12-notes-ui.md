## Что сделано

Клиентская половина FIN-12: рабочая вкладка «Заметки» в правой панели Studio (Vanilla TS + DOM, без React/новых зависимостей).

- **`apps/studio/src/collaboration.ts`** (новый, чистая модель + рендер, без DOM-состояния):
  - `loadCollaborationPanel(api, projectId, questId)` → `{kind:"unavailable",reason}` | `{kind:"ready",view}`;
  - `collaborationWriteFailure(error)` — 409 `COLLABORATION_REVISION_CONFLICT` → `{kind:"conflict",currentRevision}` (читает `error.currentRevision` из payload), 403 `COLLABORATION_FORBIDDEN`/`CONTROL_FORBIDDEN` → `forbidden`, 404 → `not_found`, 409 `COLLABORATION_IDEMPOTENCY_KEY_REUSED` → `idempotency_reused`, 400/422 → `invalid`, прочее → `error`;
  - `collaborationErrorMessage` / `collaborationLoadMessage` — человеческие подсказки вместо голых кодов (конфликт явно говорит «ничего не перезаписано» и предлагает перечитку);
  - `renderCollaborationPanel(state, options)` — HTML панели: метаданные коллекции (реальные `revision`, число заметок, открытых/всего тредов), справка `<details data-collab-help open>` с конкретным примером, баннер конфликта `role="alert"`, списки заметок и тредов, формы-действия;
  - `collabField` — сохранённый ввод, переживающий полную перерисовку `innerHTML`; `collaborationAnchorLabel`; `collaborationAnchorFromForm` (board → координаты, scene/layer/field → id цели).
- **`apps/studio/src/api.ts`**: View-типы `CollaborationView/Note/Message/Thread/Anchor` и 9 методов `ControlApiClient` (`getCollaboration`, `create/change/deleteCollaborationNote`, `createCollaborationThread`, `add/change/deleteCollaborationMessage`, `setCollaborationThreadStatus`). Все записи идут через общий `request()`: CSRF proof из памяти вкладки + обязательный `idempotency-key` (пустой ключ отсекается клиентом до запроса).
- **`apps/studio/src/app.ts`**: третья вкладка `inspector-tab data-tab="notes"` со счётчиком открытых тредов, класс `ed-body.notes-open`, состояние `collaboration*` (конфликт, busy, notice, поля форм, inline-редактирование), действия `collab-reload` / `collab-note-edit|delete` / `collab-message-edit|delete` / `collab-thread-resolve|reopen` / `collab-cancel-edit`, формы `collab-note-create|change|thread-create|thread-reply|message-change`. Загрузка панели — в `selectQuest` и при первом открытии вкладки; на все записи — `runCollaborationWrite` (CAS `expectedRevision` из скрытого поля формы), 409 рисуется баннером конфликта с кнопкой «Перечитать с сервера», 403/404 — понятным сообщением; данные до явной перечитки не подменяются.
- **`apps/studio/styles.css`**: блок `/* FIN-12 … */` — `.collab-panel{width:100%}`, `.ed-body.notes-open` (панель шире: `minmax(400px,480px)`), `overflow-wrap:anywhere` + `white-space:pre-wrap` для текстов, `padding-bottom:28px` (последняя строка скролла доступна), `text-overflow: ellipsis` отсутствует во всём блоке; на ≤1100px панель не скрывается (в отличие от общей скрытой правой панели), а переносится под рабочую область.

Требования продукта: действие (форма) стоит прямо под своим списком; вкладка содержит короткую справку с примером; данные только реальные (никаких плейсхолдеров и выдуманных процентов); read-only роль не получает ни одного write-контрола (только чтение и «Обновить»).
