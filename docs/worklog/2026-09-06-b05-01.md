# Worklog — 2026-09-06 — B05-01

## Цель

Заложить server-side authoring foundation для canonical B05 до начала Studio UI: authoritative draft, validation точного snapshot, frozen playtest, durable persistence и минимальный loopback Control HTTP.

## Реализовано

### Contracts / authoring vocabulary

- `core.action` добавлен schema-first как bounded authoring block для уже существующего `core.paint`.
- Action хранит `resourceId`, стоимость ресурса, длительность и `allowPartial`.
- Semantic validation требует существующий `core.resource`.

### Control package

Создан `@living-history/control`:

- `ProjectRecord`;
- `DraftSnapshot`;
- atomic `DraftChangeSet(baseRevision)`;
- discriminated `DraftValidationRecord`;
- `FrozenPlaytestRecord`;
- `MemoryControlStore` как reference semantics;
- `SQLiteControlStore` на built-in Node `node:sqlite`.

`draftRevision` отделён от gameplay `WorldState.revision` и Runtime fencing.

### Durable SQLite

Отдельные таблицы:

- `control_meta`;
- `control_projects`;
- `control_quests`;
- `control_draft_snapshots`;
- `control_validations`;
- `control_playtests`.

Candidate draft вычисляется вне write transaction; публикация новой revision делает compare-current-revision внутри короткого `BEGIN IMMEDIATE`.

Проверено reopen/restart и две независимые SQLite instance на одном DB.

### Control HTTP

В `apps/server` добавлен отдельный Control listener, разрешающий bind только loopback.

Реализованы:

- `GET/POST /control/v1/projects`;
- `GET/POST /control/v1/projects/{projectId}/quests`;
- `GET .../{questId}/draft`;
- `POST .../{questId}/draft/changes`;
- `POST .../{questId}/validations`;
- `POST .../{questId}/playtests`.

Validation/playtest transport не выдаёт внутренний compiled artifact целиком.

### Registry / generated docs

Available теперь 13 operations: 5 Runtime + 8 Control. Это 11 distinct HTTP paths, поскольку projects и quests имеют GET+POST.

`control.capabilities` и `control.agent-kit` остаются planned.
