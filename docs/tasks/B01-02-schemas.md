# B01-02 — канонические схемы первого слоя

## Цель

Заменить минимальный guard набором версионированных JSON Schema для первого
сквозного примера. Схемы становятся источником истины для DTO; ручные типы и
агентная документация должны ссылаться на них, а не описывать другой формат.

## Вход

- `AGENTS.md`, `docs/HANDOFF.md`;
- разделы 4–6, 10, 13 и 15 ТЗ;
- принятый B01-01 и его fixtures.

## Сделать

1. Выбрать расположение и версию схем для `ActionResult`, `Effect`, минимального
   `WorldState`, `SceneFrame` и `PresentationPlan`.
2. Добавить положительные и отрицательные fixtures только для объявленных полей;
   не придумывать ещё не реализованные endpoints или capabilities.
3. Зафиксировать правила неизвестных полей, версий и ссылок между сущностями.
4. Подключить одну воспроизводимую проверку JSON Schema и оставить текущий
   публичный TypeScript guard совместимым с ней либо явно записать границу.
5. Обновить `docs/agent/README.md`, STATUS, HANDOFF и worklog.

## Приёмка

- каждая заявленная схема имеет версию и fixture;
- валидные fixtures проходят, плохая версия/ссылка/тип отклоняются;
- TypeScript-экспорты и схема не расходятся на проверенных примерах;
- `npm run verify` проходит на чистом runner;
- diff не содержит Runtime API, хранилища, LLM или Studio.

## Не делать

Полный квестовый редактор, OpenAPI-регистратор всех будущих endpoint, генерацию
Skill целиком, миграцию Florence и плагин SDK.
