# B01-01 — минимальные контракты и границы

## Цель

Сделать первый проверяемый слой, на который смогут опираться будущие runtime и Studio. Эта карточка не реализует игру.

## Вход

- `AGENTS.md`, `docs/HANDOFF.md`;
- разделы 4–8 и 15 ТЗ;
- существующие `packages/contracts` и `packages/core`.

## Сделать

1. Согласовать и расширить типы результата действия, не смешивая игровые и processing-статусы.
2. Добавить канонические JSON fixtures для одного минимального результата и одного отклонённого значения.
3. Добавить проверку, что Core импортирует только публичный contracts entrypoint и не знает инфраструктуру.
4. Обновить краткий agent-контекст, если меняются доступные экспорты.
5. Запустить `npm run verify` и записать результат в worklog.

## Приёмка

- `npm run verify` проходит;
- неизвестный статус, отрицательное/дробное время и malformed effect отклоняются;
- processing-статусы не принимаются как игровой outcome;
- в документации нет endpoint или возможности, которых нет в коде;
- diff ограничен контрактным срезом и его проверками.

## Не делать

LLM, сетевые вызовы, SQLite, авторизацию, Studio, Player, миграцию Florence и универсальный plugin SDK.
