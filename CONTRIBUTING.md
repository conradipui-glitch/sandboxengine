# Как продолжать работу

## Быстрый цикл

```text
прочитать README → STATUS → HANDOFF → карточку Bxx
изменить минимальный срез → npm run verify
обновить документацию → записать handoff и commit
```

Коммиты делай небольшими и называй по результату (`docs:`, `contracts:`, `core:`, `test:`). Не смешивай перенос квеста, изменение дизайна и инфраструктурный рефакторинг в один commit. Перед публикацией проверь `git diff`, `git status` и точный commit, который будет отправлен.

В pull request укажи: зачем изменение, какие контракты затронуты, чем проверено, что осталось и какой следующий bounded-шаг. Если тест требует платного провайдера или живого плейтеста, пометь это отдельно; зелёная локальная проверка не заменяет такой эксперимент.
