# Визуальная приёмка Мастерской (Studio)

Здесь лежат артефакты инструмента `scripts/ui-visual-acceptance.mjs`: он проходит все
экраны Мастерской, нажимает каждый контрол и честно записывает, что не сработало.

## Как запустить самому

Понадобится собранный `dist` (в рабочем дереве его обычно нет) и Node 24.19.0:

```
node ./node_modules/typescript/bin/tsc -b --force
node scripts/ui-visual-acceptance.mjs
```

Инструмент сам поднимает свой стенд — копию базы, seed Florence (`scripts/seed-real-content.mjs`),
свой Studio на 4201, свой Control на 8911 и свой headless Chrome на CDP 9361 со своим профилем.
В основную базу он не пишет, продуктовые исходники (`apps/**`, `packages/**`, `styles/**`)
не меняет: если находится дефект, он попадает в отчёт, а не в код.

Полезные ключи: `--keep` (не удалять копию базы и скачанные файлы), `--no-seed` (не
наполнять базу), `--workdir <dir>` (куда писать артефакты), `--chrome <path>`.
Переменная `LH_UA_ONLY` — список id экранов через запятую, чтобы прогнать только их.

## Что лежит рядом

- `report.json` — машинный отчёт: экраны, снимки, каждый нажатый контрол, проблемы.
- `report.md` — тот же отчёт таблицей: «экран / тема / скриншот / вердикт» и списки проблем.
- `shots/<экран>-<тема>-<ширина>x<высота>.png` — снимки в трёх темах (тёмная, светлая,
  графит) и двух размерах (1600x1000 и 1280x900).

## Что означает код выхода

`0` — только если НЕТ: неработающих контролов (нажатие не дало ни изменения DOM, ни
запроса, ни перехода, ни скачивания), ошибок консоли, наложений видимых соседних блоков,
переливов за границы, залипшей дольше 8 с загрузки, недостижимых экранов, контролов,
которые не удалось найти, и неожиданных ответов 4xx/5xx. Иначе `1`.

Ожидаемые по замыслу ответы (404 на `/control/v1/auth/session` — так Studio отличает
локальный режим без входа) в проблемах не считаются и перечисляются отдельно.
