# Приёмка бот-управляемого входа Living History Studio (вживую, с людьми)

Контур: `https://85.137.95.104.sslip.io:8741` → страница входа → бот
**@living_history_gate_bot**. Живую приёмку с реальными людьми автоматика
провести не может (нет доступа к чужим Telegram-аккаунтам) — шаги ниже
выполняются вручную. Автотесты гейта/бота: `node --test deploy/vps/lhc-gate.test.mjs`.

Подготовка: владелец один раз пишет боту `/start` (иначе не получит заявки).
Токен — только на VPS (`/opt/lhc/engine/deploy/vps/.env`, `LHC_TELEGRAM_BOT_TOKEN`).

## 1. Вход владельца
1. В браузере без сессии открыть `https://…:8741/` → страница «Living History Studio —
   творческая мастерская» с кнопкой «Войти через Telegram».
2. Нажать кнопку → состояние ожидания + ссылка «Открыть бота».
3. В боте (аккаунт владельца) подтвердить КОНКРЕТНУЮ попытку (сверить UA/IP/время).
4. Ожидается: браузер сам открывает Studio. В боте — меню владельца
   («Добавить участника», «Участники», «Отозвать доступ», «Открыть Studio»).

## 2. Вход отдельного участника
1. Владелец в боте: «Добавить участника» → числовой Telegram ID человека.
2. Человек открывает ссылку на бота, жмёт `/start` → видит «Открыть Studio».
3. Человек в браузере жмёт «Войти через Telegram», в боте подтверждает попытку.
4. Ожидается: вход в Studio без ручных кодов.

## 3. Неизвестный пользователь
1. Человек НЕ из списка пишет боту `/start`.
2. Ожидается: понятное сообщение («доступ по приглашению, заявка отправлена»),
   владельцу приходит запрос с кнопками «Разрешить/Отклонить».
3. «Разрешить» → человек входит как в п.2. «Отклонить» → внятный отказ.

## 4. Повтор ссылки
1. Подтверждённую (или чужую) ссылку `…?start=login_…` открыть повторно / с другого аккаунта.
2. Ожидается: «попытка недействительна» / «это не ваша попытка», сессия не выдаётся.

## 5. Вход без подтверждения
1. Создать заявку на странице входа, в боте НИЧЕГО не подтверждать.
2. Ожидается: через ~2 мин страница показывает «время вышло»; прямой вызов
   `POST /gate/login/consume` до подтверждения отвечает 403 `not_approved`.

## 6. Отзыв активной сессии
1. Участник внутри Studio. Владелец в боте: «Отозвать доступ» → человек.
2. Ожидается: следующая загрузка Studio у участника ведёт на страницу входа;
   повторный вход возможен БЕЗ нового приглашения только после повторного
   добавления (закрытие браузера само по себе тоже требует нового подтверждения
   в боте, но не нового приглашения, пока права действуют).

Отметить результат каждого пункта (дата, кто проверял) — до закрытия B13.
